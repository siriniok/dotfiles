## Checks and GitHub Actions

Run `jaros ci-check` inside `nix develop`. It combines workflow lint, pre-commit,
and flake checks. The development shell provides these tools:

| Tool                    | Check                                                               |
| ----------------------- | ------------------------------------------------------------------- |
| actionlint              | GitHub workflow syntax                                              |
| nixfmt                  | Nix formatting                                                      |
| Statix                  | Nix correctness and style                                           |
| Deadnix                 | Unused Nix arguments and bindings                                   |
| ShellCheck              | Bash scripts                                                        |
| Zsh syntax and zsh-lint | Zsh scripts and startup files                                       |
| Gitleaks                | Working-tree credentials; `jaros secrets-history` scans Git history |

`.pre-commit-config.yaml` is generated by `nix develop` and ignored. Maintain the
hooks in [hooks.nix](../modules/flake/hooks.nix). ShellCheck excludes Zsh;
use `pre-commit run zsh-syntax --all-files` and
`pre-commit run zsh-lint --all-files` for its dedicated checks.

Flake regression checks cover portable standalone GNOME settings, the modern
nix-index handler, Jaros command routing, installer bootstrapping, and Codex notification decisions. They mock
external commands and desktop interaction rather than activating configurations.

Jaros, installer, and nix-index handler regression tests use Janet's standard
library and share [tests/support.janet](../tests/support.janet) for assertions,
subprocess capture, fixture cleanup, and test reporting. Jaros-specific checkout
fixtures and mocks remain under `tests/jaros.d`. Run the Jaros and installer
suites locally with `jpm test`. The handler
suite runs through the `nix-index-handler` flake check against the generated
handler, using Zsh's `zpty` module to exercise terminal-only suggestions. Codex
notification tests remain in Python alongside their Python implementation.

| Workflow                                                                        | Trigger                      | Coverage                                                                                               |
| ------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| [Nix CI](../.github/workflows/ci.yaml)                                          | Push, pull request, manual   | Checks on Linux and Apple Silicon macOS; evaluates native Home Manager profiles and the Darwin system  |
| [Nix configuration builds](../.github/workflows/build.yaml)                     | Manual; Mondays at 04:23 UTC | Builds Home Manager on x86_64/aarch64 Linux and macOS, plus the NixOS and Apple Silicon Darwin systems |
| [Update VS Code extensions](../.github/workflows/update-vscode-extensions.yaml) | Mondays at 05:47 UTC         | Updates declared extension versions and hashes, evaluates the result, and opens a PR                   |

CI never activates its builds. The routine Linux job also scans the full Git
history with Gitleaks. VS Code extension updates run only in the weekly workflow;
`jaros update` updates Nix inputs. Enable **Allow GitHub Actions to create and
approve pull requests** in repository Actions settings for the update PRs.

## Security review after changes

Run the existing development checks and history scan from the checkout after changes:

```sh
nix develop --no-update-lock-file --command janet bin/jaros ci-check
nix develop --no-update-lock-file --command janet bin/jaros secrets-history
j packages --all-platforms
```

For a separate advisory review of the active NixOS closure, use the locked scanner
and keep its output private until triaged:

```sh
umask 077
nix shell --no-update-lock-file --inputs-from . nixpkgs#vulnix \
  --command vulnix --system --json > vulnerability-review.json
```

This scans the active system, not an unactivated configuration. The root-level
`vulnerability-review*.json` reports are ignored by Git; review findings before
sharing them.

## Rootless Docker and local Actions

NixOS enables rootless Docker as a user service in
[development.nix](../modules/nixos/development.nix), without Docker group membership.
It uses separate storage under `~/.local/share/docker`; existing rootful images
are not migrated automatically.

```sh
jaros ci-plan
jaros ci-local --dryrun  # Preview act's steps.
jaros ci-local          # Run the Linux CI job.
```

`jaros ci-local` uses `DOCKER_HOST` if set; otherwise it selects
`unix://$XDG_RUNTIME_DIR/docker.sock`. It does not mount the host Docker socket
inside the runner. You can select a socket explicitly:

```sh
DOCKER_HOST="unix://$XDG_RUNTIME_DIR/docker.sock" jaros ci-local
```

Local Actions require an accessible Docker daemon and network access. The first
run downloads the runner image and creates a separate container Nix store, which
can consume substantial disk space. The runner uses Linux amd64, with emulation
on ARM; macOS jobs run on GitHub. GitHub's Nix-store cache step is skipped under
act. For API rate limits, use `jaros ci-local -s GITHUB_TOKEN` and enter the token
at its prompt.

## Package inventory

`j packages` reports evaluated Home Manager, system, per-user, development-shell,
and exported package roots, including packages added by enabled modules and system
defaults. The repository's fonts, kernel, and active service/hardware package
paths are also collected; excluded-package lists are skipped. Ruby and Emacs
environments include their explicitly selected components, and VS Code extensions
are included. It does not expand transitive dependencies
or scan the current store. When adding a new kind of service/driver package path,
extend the collector in [package-inventory.nix](../lib/package-inventory.nix).
The table shows package/version, license, author/team, and configuration scopes;
`--all-platforms` adds a platform column. Repeated package metadata is combined
within each platform. `NIX_SYSTEM` selects a single platform when needed.

The report groups free, unfree, and unknown license metadata separately. A mixed
license list containing an unfree license is classified as unfree. Nixpkgs rarely
records upstream authors; `maint:` explicitly identifies Nixpkgs maintainers/teams
when author/team metadata is unavailable. Missing metadata is shown as `-`.
The command evaluates the checkout, uses `config.local.nix` when present, and
does not build packages or modify the lock file.

## Janet commands and tests

[project.janet](../project.janet) defines the project without external Janet
dependencies. Janet and JPM come from locked nixpkgs. Inside the development
shell, use `jpm test` for Jaros and installer regression tests or `jpm run help` to list
commands. No `jpm deps` or global Janet installation is needed.

`jaros ci-home` discovers all standalone profiles and builds their activation
packages. `NIX_SYSTEM` overrides native platform detection; the CI build matrix
supplies this value. Its implementation lives in [home.janet](../bin/jaros.d/home.janet).

The entry point in `bin/jaros` loads the library under [bin/jaros.d](../bin/jaros.d):
`cli.janet` dispatches commands, `commands.janet` defines command plans,
`home.janet` builds Home Manager profiles, and `process.janet` handles subprocesses.
Tests mirror these modules under [tests/jaros.d](../tests/jaros.d), with shared
fixtures and mocked commands written in Janet. The runner is
[tests/jaros.janet](../tests/jaros.janet); it also runs directly with
`janet tests/jaros.janet`.

## Runtimes and SDKs

[runtimes.nix](../modules/home/runtimes.nix) installs Ruby 4.0 with Rake and
Node.js 26 with npm for every installation mode; `flake.lock` pins exact versions.
Use `j run` to apply; no `frum init`,
`fnm env`, or global `gem install rake` step is needed. Updating `flake.lock`
updates versions within those selected runtime lines.

The same module installs OpenJDK 25 and sets `JAVA_HOME` through Home Manager's
Java integration. Clojure explicitly uses that JDK too. Project development
shells can select another JDK when required by their Gradle/Android toolchain;
Android Studio can keep using its bundled runtime for the IDE itself.

Rust is installed directly from the locked nixpkgs input, alongside a C compiler
for linking. `RUST_SRC_PATH` points to the matching standard-library sources.
There is no Rustup download or shell initialization step. Select project-specific
toolchains and native dependencies through project Nix development shells.

[android.nix](../modules/home/android.nix) provides the minimal Android SDK:
command-line tools and platform-tools. `ANDROID_HOME` and the compatibility
variable `ANDROID_SDK_ROOT` point to that SDK. Its `latest` versions come from the
locked nixpkgs repository metadata, not a live download at activation. The SDK
composition enables acceptance of the [Android SDK license](https://developer.android.com/studio/terms).
It supports x86 Linux and both macOS architectures; Google's x86-only Linux
platform-tools archive is excluded on ARM Linux.

The SDK in the Nix store is read-only. Add required Android platforms and build
tools to `platformVersions` and `buildToolsVersions` in the module (or a project
SDK composition), then rebuild. Avoid `sdkmanager --install` against this SDK.
Emulators, system images, and the NDK are not installed by default.

For project-specific runtime versions and dependencies, use a project Nix
development shell with direnv. Remove old Frum/Fnm initialization from local
shell files if it overrides the Nix-managed defaults. Project gems and npm
dependencies remain managed by their projects' lockfiles.

Full Xcode and Apple device SDKs are macOS-only and must be obtained from Apple.
Nix's macOS compiler includes a fallback SDK for ordinary native builds. If you
need full Xcode, install it from the Mac App Store and run its one-time setup:

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
```
